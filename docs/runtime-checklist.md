1~5단계 업데이트(`docs/maintenance-backlog.md`) 이후, 빌드·린트로는 확인할 수 없는 실제 동작을 점검하는 순서입니다.
**위에서부터 순서대로** 진행하고, 통과한 항목은 `[x]`로 바꾸세요. 실패하면 `> 결과:` 줄에 증상(화면 메시지, 콘솔/터미널 로그)을 적어 두면 다음 세션에서 바로 이어서 고칠 수 있습니다.

준비물: Chrome 등 브라우저와 개발자 도구(F12), **승인된 일반 계정 1개**와 **관리자 계정 1개**(Google), 문의 데이터 6건 이상(9단계 페이지 이동용)

## 0. 준비

- [ ] 프로젝트 루트에서 의존성을 설치합니다. lockfile이 바뀌었으므로 꼭 필요합니다.

  ```bash
  pnpm install
  ```
- [ ] `node -v`의 결과가 **v24.x**인지 확인합니다. `package.json`의 `engines`가 `24.x`로 설정되어 있습니다.
- [ ] `.env`에 `GEMINI_API_KEY`, `OPENAI_API_KEY`, Firebase·MongoDB 관련 키가 들어 있는지 확인합니다. 값을 바꿀 필요는 없습니다.

## 1. AI 모델 연결 점검 (앱 실행 전)

앱 화면에서는 Gemini 1순위 모델만 호출됩니다. OpenAI 경로는 `app/api/generate/route.ts:63`에 `"gemini"`로 고정되어 있어 앱에서는 호출되지 않습니다. 그래서 폴백 모델과 OpenAI 모델은 이 스크립트로 따로 확인합니다.

- [x] 다음 명령을 실행합니다.
  ```bash
  node scripts/check-ai-models.mjs
  ```
  > 결과(2026-10-18): `--gemini`로 실행, Gemini 3개 모델 모두 OK (1.4~1.7초). OpenAI(`gpt-6-luna`)는 처음에 `400 Unknown parameter: 'modalities'`로 실패 → `openai-route.ts`·스크립트에서 `modalities` 제거 후 OK (2.2초). `reasoning_effort: "none"` + `temperature: 0` + `json_object` 조합은 정상 동작 확인
- [ ] 다음 4줄이 모두 `✅ OK`로 나와야 합니다.
  - `Gemini  gemini-3.6-flash`
  - `Gemini  gemini-3.5-flash-lite`
  - `Gemini  gemini-2.5-flash`
  - `OpenAI  gpt-6-luna`
- 실패했을 때:
  - **OpenAI 줄이 `400 ... temperature` 같은 메시지로 실패하면** `app/api/generate/openai-route.ts`에서 `temperature: 0`을 빼야 합니다. 스크립트의 같은 부분도 함께 고친 뒤 다시 실행합니다.
  - **`response_format` 관련 400 오류이면** `json_schema` 방식으로 바꿔야 합니다.
  - **Gemini 모델 중 하나만 실패하면** 앱은 다음 모델로 넘어가므로 당장 장애는 아닙니다. 모델명이 지원 종료되었을 수 있으니 기록해 둡니다.

## 5. 계정 메뉴 접힘 동작 (린트 수정으로 바뀐 부분: FloatingAccountControls)

창 폭은 F12의 기기 툴바(Ctrl+Shift+M)에서 너비를 직접 입력해 바꾸면 편합니다. 기준 폭은 메인 `/`가 **768px**, `/inquiry`·`/mypage`·`/admin`이 **1024px**입니다.

- [x] 메인 `/`, 폭 1200px, 분석 엔진이 닫힌 상태: 우측 상단에 계정 버튼 패널이 **펼쳐져** 보여야 합니다.
- [x] 분석 엔진을 열면(전체화면 상태) 패널이 **십자(+) 버튼**으로 접혀야 합니다.
- [x] 십자를 누르면 회전하며 패널이 펼쳐지고, **패널 바깥을 클릭**하면 다시 십자로 접혀야 합니다.
- [x] 분석 엔진을 닫으면 패널이 다시 펼쳐진 상태로 돌아와야 합니다.
- [x] 메인 `/`에서 폭을 **700px**로 줄이면 십자로 접히고, **800px**로 늘리면 다시 펼쳐져야 합니다.
- [x] 폭 700px인 상태에서 **새로고침(F5)**했을 때 로딩 후 십자로 표시되고, Console에 `Hydration` 관련 경고가 없어야 합니다.
- [x] `/inquiry`에서 폭 1000px이면 십자, 1100px이면 패널이 펼쳐져야 합니다.
  > 결과(2026-10-18): 좁은 폭에서 새로고침하면 십자 대신 패널이 보임(`/`, `/inquiry` 모두). Hydration 경고는 없음. 원인은 린트 수정 때 생긴 회귀: 인증 로딩 후 클라이언트에서 처음 마운트될 때 `expanded` 초기값이 접힘 조건을 반영하지 않음. `expanded` 초기값을 `!collapsible`로 수정함 → 재확인 통과
